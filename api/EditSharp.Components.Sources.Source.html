Remarks

Compositing and mixing never know what kind of source they're reading. They prepare it, open readers on it, and react to the SourceUnavailableReason a failed read reports.

A source is plain data. Its [Editable] properties are exactly what SourceSerializer saves, and Duplicate() round-trips through the serializer, so a new property is copied exactly when it's saved. Nothing prepared or opened (probe results, decoders) is kept on the source, so several Playbacks can read one source at once.

To add a kind, derive from VideoSource or AudioSource, mark the class [SourceKind("stable-id")], implement PrepareAsync and GetNaturalLengthAsync(CancellationToken), and add whatever identifies its content to AddFingerprint. The id is written into saved files, so it must never change. BlenderSceneVideoSource and VSTInstrumentSource show the bare shape.
