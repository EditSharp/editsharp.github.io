Remarks

A graph can have any number of inputs, or none; one that reaches the output node is what makes a clip show or play anything. An input owns everything about how its content is used: the window of it the clip plays (Start, Duration, Loop) and every kind-specific setting, keyframed ones included, so its animations live on the node like any other node's. A kind that reads an IMedia holds it as a property; the media itself knows nothing about clips.

Trimming a clip's head moves every input's in-point in its graph by the same amount, limited by whichever has the least room.

To add a kind, derive from VideoInputNode or AudioInputNode, mark the class [NodeKind("stable-id")], implement PrepareAsync and GetNaturalLengthAsync(CancellationToken), and list any Animatable properties in Animatables. Copying and saving come for free: an input's [Editable] properties are exactly what ComponentSerializer saves, and Duplicate() round-trips through it. The id is written into saved files, so it must never change.
