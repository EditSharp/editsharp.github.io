The one proxy per original media file; shared by scrubbing, playback and paused editing alike. An entry remembers its original (by content hash, so a renamed, moved or duplicated file finds the same proxy), its format, and how far it has been built.

NOTHING BUILDS AUTOMATICALLY. A consumer calls BuildAsync (typically on import) and watches StatusChanged; everything that reads media only ever looks proxies up. Builds queue behind EditSharpConfig.MaxConcurrentProxyBuilds; concurrent requests for the same file share one build, which is cancelled only once every caller has cancelled.

PARTIAL PROXIES ARE FIRST-CLASS: a proxy is readable from its start up to AvailableUpTo while it builds, stays readable if the build is interrupted (ProxyState.Partial), and the next BuildAsync resumes from there. Building a different format than the one on disk replaces it: the old proxy keeps serving reads until the new one completes, then is deleted.

ON DISK (EditSharpConfig.ProxyDirectory/<hash[..2]>/), one stem per format (<hash>.delta7, .rgba, .dnxhr, .prores) so a replacement never collides with the proxy it replaces: <stem>.esrp an .esrp proxy (progress lives in its index) <stem>.mov.json a MOV proxy's sidecar (segments/progress) <stem>.seg<n>.mov, <stem>.mov its segments while building, its final file once complete

BuildAsync(string, ProxyFormat?, IProgress<double>?, HardwareAccelerator, CancellationToken)

Builds sourcePath's proxy in format (EditSharpConfig.ProxyFormat when null), resuming a partial one of the same format, and returns once it's complete. Returns at once if a complete proxy in that format already exists. Cancelling only detaches this caller; the build itself stops when no caller is left waiting on it, and what it wrote stays usable and resumable.
